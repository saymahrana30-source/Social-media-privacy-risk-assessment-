# Interview preparation - 10 questions and answers

**1. Explain your project.**
It is a Social Media Privacy Risk Assessment Framework. A person answers 56 questions about their settings and habits - for example whether their phone number is public or whether MFA is on - and never types the data itself. My Flask backend validates the answers, turns them into risk values, scores ten categories from 0 to 100, combines them with configurable weights into an overall score, classifies it as LOW, MODERATE, HIGH or CRITICAL, and then generates ranked findings, prioritised recommendations and a what-if simulation. It stores only scores and finding types, and I tested it with 52 automated tests.

**2. What is the difference between privacy and security?**
Privacy is about controlling how personal information is exposed and used; security is about protecting accounts and systems from unauthorised access. You can have strong security and weak privacy - MFA plus a public phone number and travel plans. My synthetic dataset has a "secure but open" archetype to show that.

**3. What is a digital footprint?**
It is the trail of information about you online. Active footprint is what you deliberately post; passive is data generated by your activity. I assess only self-reported practices such as old posts, unused accounts, public comments and whether you review settings.

**4. How can oversharing lead to social engineering?**
Public details like employer, college, travel plans and family make a scam message more believable. The project teaches this conceptually and recommends verification through a second channel and never sharing verification codes; it contains no attack scripts.

**5. How does your privacy-risk scoring work?**
Each answer maps to a risk value between 0 and 1 (YES to "phone public" is 1, NOT SURE is 0.6, NO is 0). A category score is the question-weighted average times 100. The overall score is a weighted average of category scores - for example location and account security are 15% each - then rounded and classified at 20, 40 and 70. I state clearly that weights and thresholds are educational assumptions that need calibration before any professional use.

**6. How did you apply data minimisation?**
There are no free-text fields, the questions ask only "is it visible?", extra fields are rejected, and the database holds only assessment id, scores, finding types, severity and timestamp. The raw answers are never stored; the simulator uses answers kept in the browser tab only. A test inspects the database to prove no sensitive columns or values exist.

**7. How does MFA help?**
MFA requires a second proof, like an authenticator code or security key, so a stolen or reused password is not enough. It is weighted HIGH severity in my model, and the recommendation is the strongest method the platform supports.

**8. Why do third-party applications matter?**
Each connected app can read or act on your account, and old integrations are easy to forget. I apply least privilege: review connected apps, remove unused ones, limit broad permissions and "Sign in with" links.

**9. What is Privacy by Design and where is it in your project?**
It means building privacy in from the start: data minimisation, purpose limitation, privacy by default, transparency, user control, retention limitation and secure processing. Examples: scores-only storage, a 30-day automatic purge, a delete endpoint protected by a one-time token stored as a hash, on-screen notices and CSP/rate limiting.

**10. How did you test it?**
I wrote 52 pytest tests: fully private and fully public profiles, one test per risky setting, boundary tests at scores 20, 40 and 70, category and overall calculation, recommendation generation and the simulator. Security tests check that sensitive data is not stored, XSS is escaped in the report, rate limiting returns 429, oversized bodies are rejected, deletion needs a token and cascades, and error messages do not leak internals. A script turns the real run into `docs/TEST_RESULTS.md`.
